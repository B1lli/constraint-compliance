# Contributing

Thanks for taking the time. This project is small and opinionated; the notes below save everyone a round-trip.

## Setup

```bash
git clone https://github.com/B1lli/constraint-compliance.git
cd constraint-compliance
git config core.hooksPath .githooks   # enables the pre-commit and commit-msg checks
python3 -m unittest discover -s tests
```

Python 3.8+ with the standard library only. No dependencies to install.

## What the hooks enforce

`scripts/check_markers.py` runs on every commit (staged content and the commit message). It refuses AI co-author
trailers and "generated by" watermarks, vendor and model names, and model ids. The two
host product names the skill must mention to be installable are allowed. Run it by hand over the whole tree with:

```bash
python3 scripts/check_markers.py --all
```

## Changing `SKILL.md`

- The six-section body mirrors the version shipped inside the production assistant it came from. Keep edits to the body minimal and explain in the
  commit message why the wording changed.
- The `description` is the trigger. It is deliberately short: in our measurements a 683-character description was never
  picked up on a real-incident case (0 of 11 runs) while a 128-character one was (2 of 2). Do not add scenarios,
  document types, or keyword lists to it. If you believe a change helps, include before/after trigger counts on a
  positive case **and** a negative control.
- Validators are advisory. Do not turn `gate_check.py` into a blocker of the agent's flow.

## Adding a validator type

1. Implement it in `run_one_file` in `scripts/gate_check.py`; return `(bool, note)` or `(None, note)` when undecidable.
2. Add a positive and a negative control to `tests/test_gate_check.py`. A validator without a test that turns red is not done.
3. Document it in `docs/validators.md`.

## Commits and pull requests

- Conventional Commits, one logical change per commit. Chinese or English are both fine.
- CI must be green: unit tests, the runnable example, and the marker check.
- Please do not paste real user conversations, customer names, or internal links into fixtures or docs. Fixtures are
  synthetic by design.

## Reporting a case where the skill did not fire or did not hold

Open an issue with: host (Claude Code / Codex / other), how the rule was persisted (project instruction file,
memory note, learned item), the number of other skills present, whether the request repeated the rule verbatim,
and what the artifact looked like. "Fired but the artifact still violated the rule" and "did not fire" are different
bugs; say which one you saw.
